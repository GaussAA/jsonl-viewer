## Purpose

Git hooks managed by husky v9 (installed by the `prepare` script, `"prepare": "husky"`). Hooks are intentionally split: a fast pre-commit and a heavier pre-push, with CI remaining the final authority. Excluded from the VSIX.

| `pre-commit` | Runs `node node_modules/oxlint/bin/oxlint && node node_modules/prettier/bin/prettier.cjs --check .` (about 20ms + 1–2s). ## For AI Agents

### Working In This Directory

- Edit only `pre-commit` and `pre-push`. Add new hooks as plain files named after the git hook; do not touch `_/`.
- Keep hooks POSIX `sh` and dependency-free beyond `node_modules` binaries; they run on Windows (Git Bash), macOS and Linux.
- Keep the pre-commit fast. Anything slower belongs in pre-push or CI.
- `git commit --no-verify` / `git push --no-verify` bypass the hooks; do not use them unless the user asks.
- `pre-commit` fails if any untracked, non-ignored temp file is unformatted, because Prettier reads `.gitignore`. Put scratch output in `.scratch/`.
- The comment in `pre-commit` mentions "290 test cases"; that number is stale-prone and not enforced.

### Testing Requirements

- After editing a hook, run it directly (`sh .husky/pre-commit`, `sh .husky/pre-push`) from the repo root.
