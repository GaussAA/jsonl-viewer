## Purpose

Unit tests for `src/host/`. They use `node:test` and `node:assert/strict` (two files use `describe`/`it` and plain `node:assert`), run directly as TypeScript through `--experimental-transform-types`, and need no VS Code. Most tests build real temp files; the engine/indexer-level tests use in-memory readers. Test names and header comments are Chinese and usually describe the incident the test guards against; read the header before changing a test.

## For AI Agents

### Working In This Directory

- Imports use `.ts` extensions; the module under test is `../<name>.ts`. Type-only imports use `import type`.
- Do not use constructor parameter properties, enums or namespaces in test helpers (type stripping cannot handle them).
- Put scratch output in the OS temp dir (below), never in the repo; stray files break `pnpm format:check`.

### Testing Requirements

- Run one file: `node --experimental-transform-types --test src/host/__tests__/<file>.test.ts`
- Run the host suite: `node --experimental-transform-types --test "src/host/__tests__/*.test.ts"`; everything: `pnpm test`; CI coverage gate: `pnpm test:coverage:gate` (lines 96 / branches 86 / functions 88).
- Make tests able to fail: write-path tests should assert on disk bytes and on a follow-up query, not only on the return value.
- Avoid timing assertions based on tick counts (Windows timer resolution is ~15ms). Poll for a condition, as in `staleWatch.test.ts`.

### Common Patterns

- Temp files: `mkdtemp(join(tmpdir(), '<prefix>-'))`, written with `writeFile`, removed in a `finally` with `rm(dir, { recursive: true, force: true })`. Prefixes in use: `jsonl-ds-`, `jsonl-hostsync-`, `jlv-filewriter-`, `jlv-bak-`, `jsonl-export-`, `jsonl-fb-`, `jsonl-fb-ds-`, `jsonl-fb-none-`, `jsonl-cancel-`, `jsonl-tailfollow-`.
- Per-file helpers, not shared: `makeFile(dir, lines)` (writes `data.jsonl`, trailing `\n`) and `makeService(file)` in `dataService.test.ts`; `withDir(fn)` in `exporter.test.ts` and `tailFollow.test.ts`; `withService(fn)` in `queryCancellation.test.ts`; `makeCtx()` in `searchEngine.test.ts` and `profileEngine.test.ts` (`LineIndex.build([buf])` + `MemoryReader`); `collector()` in `logging.test.ts`; `makeFake()` in `serviceRegistry.test.ts`. There is no common helper module; copy the pattern rather than introducing one unless several files need the same change.
- Fakes and seams: `DataServiceOptions.hostFactory` (spy on hosts), `WorkerLike` / `FakeWorker` (drive `WorkerIndexHost` branches without threads), `startStaleWatch({ pollMs })` with a tiny interval, `ExportOpts.maxLineBytes` to force skipped records, `ReplaceLineOpts.blockSize` / `maxTailBackupBytes` to hit chunk boundaries cheaply.
- Large-input tests use small overrides of the limit (for example `RECORD_INLINE_MAX_BYTES`, `MAX_SELECTION_LINES`) rather than allocating GB-size files; real big-file benchmarks live in `src/perf/`.
- Sidecar assertions use the constants (`TAIL_BACKUP_SUFFIX`, `TAIL_BACKUP_META_SUFFIX`, `REWRITE_TEMP_SUFFIX`, `EXPORT_TEMP_SUFFIX`) via `readdir` to prove nothing is left behind.
